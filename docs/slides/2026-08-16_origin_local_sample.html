Origin local sample — make the origin path mirror the point path

Decision (2026-08-16): the origin depth head ẑq gets the same grid_sample local feature the interaction-point depth head ẑp already has — sampled at origin_uv. This reverses the gen-7 call to keep ẑq condition-only, because the pixel under a well-localized origin is typically the visible hinge seam itself (the gen-7 viz batch showed the origin heatmap firing on hinges, and 99.6–100% of q* projections are in-frame), so its appearance IS depth evidence — same as the handle pixel is for ẑp.

The two paths, before and after

INTERACTION POINT (unchanged, gen-7 → now)
ORIGIN (gen-11: now identical in structure)
History of the asymmetry: gen-7 kept ẑq condition-only on the assumption that the pixel under the origin is often occluded or off-object ("no real semantic meaning"). Evidence since then points the other way for the typical case: q* is the perpendicular foot from the interaction point, which for door-class objects lands on the door/frame seam at handle height — a visible surface whose depth ≈ the hinge's depth — and the gen-7 viz batch showed the origin heatmap localizing exactly those seams. The occluded minority still exists; the head keeps the full condition vector so it can learn to discount the local feature there. The remaining (intentional) asymmetries are supervision-side: origin losses run on revolute rows only and the whole origin path is unsupervised on prismatic, where no origin exists.

Implementation sketch (gen-11 candidate, flag-gated)

use_origin_local_feature: false (new ModelParams flag). When true: origin_depth_head_g7 input dim becomes vae_condition_dim + fpn_out[1]; forward adds one grid_sample(fq, origin_uv) (same expression as the point path's) and concatenates. No loss changes — ẑq keeps training purely through the composed 3D origin loss. Loop-free: the sampled feature produces a depth, never a location.
