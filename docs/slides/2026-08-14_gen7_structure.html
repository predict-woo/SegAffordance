Gen-7 proposal: heatmap + depth lifts

Everything spatial reads out of the image; everything metric is one scalar away. All 3D in camera frame, meters.

PROPOSAL — discussed 2026-08-14, not yet a spec. All design questions CLOSED (gen-6 eval in, every open item decided) — ready to spec on user go-ahead.

The gen-6 diagnosis this fixes

Gen-6's articulation heads work (direction 5–19° on grounded panels, type CE near floor) — but both 3D points (interaction $\hat{p}$, origin $\hat{q}$) were bare MLP regressions from one pooled vector: no pixel grid, no structural tie to the mask, no dense localization supervision on the trunk. Result: regression-to-the-mean 3D points, grounding failures, origin ~0.9 m RMS. Gen-7 gives both points the spatial machinery the mask always had — and the measured excuse for not doing so is gone: on v2 data the projected origin target $q^*$ is in frame 99.6–99.7% of the time (filtered and unfiltered alike; tools/diag_origin_inframe.py).

The structural constraint is back, twice: mask, point heatmap, and origin heatmap come from the SAME projector, so "the point lies on the object the mask found" is architecture, not a learned hope — and now the hinge gets the same treatment. And because each 3D point is constructed by unprojecting through its own predicted pixel, "the projected 3D point lands on its heatmap peak" holds by construction — no consistency loss needed.

Why this shape survives 2D-only pretraining

depth heads $\hat{z}_p$, $\hat{z}_q$train (through the composed 3D losses)idle — no depth GT needed, no depth-map lookup anywhere

No branch in the architecture — the 3D lift only exists where K and 3D GT exist. This is the property that ruled out depth-map unprojection: the model must not need a depth input to produce its point.

Design decisions — all closed (+ watch items)

  • DECIDED (user): mask-pooling teacher forcing returns — GT mask at train, predicted at val/test (the classical policy, `pool_with_predicted_mask: false`). Gen-6's evidence: predicted-mask pooling fed every head diluted features while masks were patchy, and unfreezing CLIP didn't fix the masks — clean object features during training matter more than the train/deploy pooling mismatch.
  • DECIDED (user): origin_uv joins the condition vector alongside point_uv — direction head sees the hinge–handle geometry (axis ⊥ the p–q image vector, radius ≈ its length), trajectory head sees its pivot, depth heads see both anchors. Gradient flows through soft-argmax (classical convention). Watch item: on prismatic rows the origin channel is unsupervised, so downstream heads must learn to ignore its readout there — if pathological, feed it detached (one line).
  • DECIDED (user): local feature sampling for $\hat{z}_p$ only — the point-depth head reads [condition vector, grid_sample of decoder features at point_uv]: the element pixel shows a real surface whose local appearance carries depth cues. $\hat{z}_q$ stays condition-only: the origin pixel has no reliable semantics (the hinge line often crosses featureless wall/frame/background), so a local sample there would be noise dressed as signal.
  • Trajectory watch items (user decision accepted, risks on record): direct absolute per-point readout reverses two documented fixes — (1) the zigzag point-cloud failure that delta-cumsum solved (viz/20260803_sf3d_twist_traj_points), (2) absolute-3D-from-pooled-vector is the exact pattern that scored 0.58 m in gen-6 (mitigated here by point_uv/origin_uv in the condition + dense trunk supervision, but unproven). Both old paths stay flag-gated; fallback is a config flip.
  • DECIDED (user): origin depth fully masked on prismatic — $\hat{z}_q$ (and the whole origin stack: heatmap BCE, $L_{origin\_3d}$) receives gradient from revolute rows only; prismatic rows contribute nothing, no auxiliary prior task. Matches how the origin was handled in gen-6 and keeps "a translation has no axis location" exact in the losses.

Inference decode (all linear): type = argmax of type logits · axis line = $(\hat{q}, \hat{d}/\lVert\hat{d}\rVert)$ · radius = dist($\hat{p}$, axis line) · trajectory is already absolute · free consistency readout: $\lVert \hat{p} - \text{traj}[0] \rVert$ (the deliberate double-prediction of the interaction point). Eval metrics: mIoU, point_err_3d_m, origin_err_m, origin_line_err_m, radius_err_m, axis angle err, type acc, traj MSE / traj_dir_acc. Idle on 2D pretraining: origin heatmap BCE, both depth heads, both 3D losses, L_trajectory, L_pp, L_motion, L_type — the mask, point heatmap, and 2D-track losses carry the pretraining.
Measurements this design rests on: origin/$q^*$ in-frame 99.6–100% on both filtered and unfiltered v2 splits (1,500 revolute samples each); $q^*$ border margin median ~19% of the long side — soft-argmax has room. Gen-6 evidence: direction/type strong, both regressed 3D points weak, grounding failures on random-draw panels.
