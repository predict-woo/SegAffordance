What "Detach the Anchor" Actually Does — and Why the Type Gate Didn't Care

Two questions, one page. First: detach changes NOTHING about what the loss computes — it only changes which weights receive the error signal when the loss is backpropagated. Second: the type head's only teacher in 2D-only training is a completely different channel that the detach neither broke nor fixed — which is why type sat at the majority baseline in every arm.

1 · Detach = same forward, cut backward

BEFORE — gradients flow everywhere the values came from
AFTER — detach: identical values, one receiver
The subtlety people trip on: detaching does NOT freeze the anchor. Every training step still uses the CURRENT predicted point (the anchor keeps getting better as the heatmap losses improve it) — the projection loss just stops being one of its teachers. Division of labor: heatmap/coord teach WHERE, the projection loss teaches the curve's SHAPE from there. Result: masks 0.057→0.242 mIoU, point 0.307→0.117, shape 0.16→0.0997.

The detach operated on the blue data-term path (§1); the type head hangs off the purple consistency path (§2). Fixing the first recovered everything downstream of the trunk — but the gate's channel was never broken by the anchor bug and never fixed by the detach: it is weak by construction. All three 2D arms sit within ±2 points of the always-trans baseline; type was never learned in any of them.

The way out (parked, not yet run): the GT 2D tracks themselves carry type information — drawer tracks are straight, door tracks are (usually) curved in projection. A straightness statistic on the GT track = a legitimate 2D-only pseudo-label; a CE on confident pseudo-labels (abstain on edge-on ambiguous ones) would restore the DIRECT appearance→type channel of the top diagram without touching a single 3D label — and a working gate would in turn unlock the origin/axis training that the circle branch's deadlock currently blocks.
