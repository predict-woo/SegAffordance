2D-Only Training on the Gen-17 Stack

Train the exact gen-17 architecture (dinov3 @512, split axis heads, origin heatmap, shared trajectory) with zero 3D ground truth: 3D trajectories, axes, origins, and type labels are reserved for evaluation. Supervision is image-space only — the GT mask, the 2D interaction point, and the observed 2D motion track — plus the model's own internal consistency. The twist-era proof (20260804_sf3d_2donly: "mechanism works, signal weak") needed a twist head and an ω-prior; the split-head family replaces that whole chain with two things it already owns: the projection loss (data term) and the normalized L_pp (GT-free consistency term).

1 · The model, colored by what trains it

Zero architecture change: this is the g17 model verbatim. "2D-only" is a loss configuration — all 3D-GT loss weights zeroed, the projection weight turned on. That also means a 2D-pretrained checkpoint loads directly into the 3D finetune with no surgery.

3 · The three design decisions (and the lessons they encode)

Normalize the projection residual per row.

The raw term is index-matched MSE in uv² — big drawer pulls dwarf small door arcs exactly the way the 3D MSE did before gen-16, and the calibration trap that caused the rot-collapse would be rebuilt in 2D. Same fix, same shape: per_row_mse / gt_track_energy.clamp(min=eps) over the valid points, flag trajectory_proj_normalized. A collapsed projected curve scores ~1.0 for every row, rot and trans alike.

Let p_rev float; add no ω-prior analog. [2026-08-21: type never emerged — unsupervised, unreported.]

The twist-era 2D-only arm needed an |ω| Occam prior and still collapsed type to trans. The split family is structurally better off: p_rev's two branches are DIFFERENT geometric models of the same track, and picking the better-fitting one lowers the loss — type becomes model selection, grounded (index 1 = circle = rot) rather than emergent-and-unanchored. Risk of collapse to one branch remains; we log the batch-mean p_rev during training and keep a parked batch-balance prior as the fallback knob rather than adding it up front (YAGNI — the 2donly failure had no branch-competition mechanism; this does).

Anchor z_p to the input depth; leave z_q to L_pp.

L_pp's circle needs the lifted point and origin (c = origin − point). The projection chain anchors the CURVE with an input-depth lookup, but the z_p head itself would drift with no 3D point loss — a cheap GT-free tether (depth_anchor_weight: masked |z_p − D(point_uv)|²) keeps the lift honest. z_q has no surface guarantee (hinge pixels sit on the door plane only approximately), so it trains through L_pp alone — accepted as the weakest link.

Eval runs the standard test pass (3D GT is exactly what SF3D reserves for this). Success is NOT g17 parity — it is (a) type separation and trajectory direction far above chance with zero 3D labels, and (b) the real payoff experiment: finetune g17-recipe from the 2D checkpoint vs from scratch — does 2D pretraining buy anything? That two-stage comparison is the reason this stage exists.

Scope honesty: SF3D's 2D tracks are projections of its synthesized 3D GT, so this is a supervision ablation (same framing as the 2026-08-04 proof), not yet "learning from YouTube." The pieces that would NOT port to real video: GT-mask pooling (switch to pool_with_predicted_mask), sensor depth (needs monocular depth), and the clean per-frame intrinsics. Everything in the colored diagram above ports as-is.
