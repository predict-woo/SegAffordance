Gen-17: Split Articulation Heads (rot / trans axis readouts)

One change, confined to the articulation module: today ONE 3-vector readout serves as both the revolute hinge axis and the prismatic slide direction. Those are different physical quantities (the hinge axis is perpendicular to the motion; the slide direction is the motion), so on type-ambiguous samples the single head's optimum is a blend of the two answers — wrong for both. Gen-17 gives each type its own tiny readout on the same trunk. Trajectory head, origin path, point path, masks: all untouched.

1 · Side by side — the articulation module only

Current (gen-6 … gen-16) — MotionMLP

The head never sees the type (the GT hint was removed in gen-7), so it must infer it from the same features — and under ambiguity its cos-optimal output is a probability-weighted blend of the two type-conditional answers.

Gen-17 — split readouts, shared trunk

Each readout is Linear(256, 3): the split adds ~770 parameters. No gradient from trans rows ever reaches the rot readout (and vice versa); the trunk still learns from every row.

2 · Why the shared head averages — and what the split does about it

This is the documented drawer/door failure (g8 close-up batches: "trans pull vs GT rot" conflicts). Beyond ambiguous samples, the split also removes gradient interference on unambiguous ones: door hinge-axis statistics (mostly vertical) and drawer slide statistics (mostly horizontal, out of the cabinet face) no longer fight over the same 771 readout weights — the same style of cross-type pressure that drove the rot-sweep collapse in the trajectory loss.

What this is NOT: not a sigmoid change (the sigmoid + rescale was investigated 2026-08-18 and is fine — every direction is representable); not the old WTA hypotheses (selection here is supervised by the type label, not winner-takes-all); not a trajectory change. Checkpoint note: the state dict gains motion_head_trans and renames nothing if we keep motion_head as the rot readout — but a from-scratch run on the g16 recipe is the plan anyway, so the arms stay comparable.
Honest risk: type errors become mode errors — a misclassified drawer now gets a decisive full hinge-axis instead of a mushy blend. Type accuracy is 92.3% on g16, so ~8% of rows take that trade. The new sign-aware metrics (flip rate, MA_signed) plus the legacy columns will show exactly which way it nets out.
